# BECK / PHOTO — Public Site

A fully independent sibling of the family photo site (`beck-photo-site`).
It started as a full copy of the original so design changes can be judged
against it, and it is evolving into the public-facing gallery.

**Independence guarantee:** either site could be deleted tomorrow and the
other would be unaffected. They share one Cloudflare R2 bucket for storage,
but keep completely separate data files — no site ever reads or writes the
other's index or config.

## How the two sites share the bucket

| File in bucket | Family site | This (public) site |
|---|---|---|
| `albums.json` | Reads + writes (its own admin) | Never touches |
| `albums_public.json` | Never touches | Reads + writes (its own admin) |
| `site_config.json` | Reads + writes | Never touches |
| `site_config_public.json` | Never touches | Reads + writes |
| `<album-id>/manifest.json`, `<album-id>/thumb/...`, `<album-id>/display/...`, `<album-id>/original/...` | Its albums | Its albums (`pub-`-prefixed IDs) |

Photo storage keeps the original key layout. Album IDs generated by this
site are prefixed `pub-` plus a short random suffix (e.g.
`pub-2026-10-17-fall-classic-x7k2`), so they can never collide with IDs
from the family site — even though both upload into the same bucket.

## Family vs. public album separation

Two layers:

1. **Separate indexes.** This site only ever reads `albums_public.json`.
   Albums uploaded on the family site are invisible here, and vice versa.
2. **`visible_categories` filter.** Within this site, an album appears on
   the homepage and category pages only if its `category`
   (case-insensitive) is checked in `site_config_public.json`.

**Fail-safe default:** if `site_config_public.json` does not exist yet,
`visible_categories` is empty and the public site shows a "galleries coming
soon" state until the owner picks categories in `/admin`.

## Pages

- `/` — Homepage: splash screen (full-screen cycling covers, "Enter
  Gallery", skipped on return visits), hero, horizontally scrollable
  category pill bar (scales to 15+ categories), and a showcase of the 3
  latest albums.
- `/category/[slug]` — Category gallery.
- `/album/[...id]` — Album viewer: downloads, slideshow, viewer-presence
  badge, and the rebuilt share sheet. A prominent **"See more albums"**
  button links back to the homepage — this is the landing page when someone
  opens a shared album link.
- `/admin` — Password-gated studio: full upload pipeline (drag-and-drop,
  in-browser processing, cover selection, reorder), album list with edit /
  delete, and site settings (branding, visible categories, homepage
  showcase count). Writes only to `albums_public.json` and
  `site_config_public.json`.
- `/admin/edit/[id]` — Edit an existing album (add/remove/reorder photos,
  change title/date/category/cover).

## Sharing (rebuilt from scratch)

The old share modal was replaced with a clean Google Photos-style share
sheet: big copy-link field, Text, Email, and QR code options. The shared
URL is the plain album URL — opening it lands directly in the album, with
the "See more albums" button as the path back to the full site.

## Environment variables

| Variable | Where | Purpose |
|---|---|---|
| `NEXT_PUBLIC_R2_BASE_URL` | Build + runtime | Public base URL of the R2 bucket, e.g. `https://pub-xxxx.r2.dev`. Used for all public reads. |
| `R2_ENDPOINT` | Server only | S3 API endpoint, e.g. `https://<account-id>.r2.cloudflarestorage.com`. Needed for `/admin` (uploads + saves). |
| `R2_ACCESS_KEY_ID` | Server only | R2 API token key. Needed for `/admin`. |
| `R2_SECRET_ACCESS_KEY` | Server only | R2 API token secret. Needed for `/admin`. |
| `R2_BUCKET_NAME` | Server only | Bucket name (same bucket the family site uses). Needed for `/admin`. |
| `ADMIN_PASSWORD` | Server only | Password for `/admin`. Set a strong one in Vercel. |

Without the `R2_*` / `ADMIN_PASSWORD` vars the site still runs fine; only
`/admin` is disabled.

## Local development

```bash
npm install
cp .env.example .env.local   # then fill in NEXT_PUBLIC_R2_BASE_URL at minimum
npm run dev
```

## Deploy on Vercel

1. Push this directory to the `beck-photo-public` GitHub repo.
2. In Vercel: **Add New Project** → import the repo. Framework preset: Next.js.
3. Add the environment variables above (all of them for a working `/admin`).
4. Deploy. Visit `/admin`, sign in, upload albums, and check the categories
   you want public. Save.
